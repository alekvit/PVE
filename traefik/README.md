# 🔄 Самообновление Traefik

Данное программное обеспечение является исполняемым письмом на диалекте баш (англ. bash-script; далее по тексту - приложение) для обеспечения автоматизированного обновления двоичного файла Traefik на Linux-серверах. 

Работает по принципу **«запустил и забыл»**: самостоятельно осуществляет проверку наличия новой версии, сверяет контрольные суммы, создаёт резервную копию исполняемого файла, осуществляет установку и управление службой (запуск/перезапуск).

## ⚠️ Критически  важное замечание ❗❗❗

**ЗАПРЕТ на ручное прерывание обновления (Ctrl+C).** Приложение перезаписывает бинарный файл и управляет systemd‑службой. Принудительное завершение может оставить систему в промежуточном состоянии: старый бинарник удалён, новый ещё не активирован. Если нужно протестировать поведение без реального обновления — запускайте на тестовом стенде.

## 🚀 Ключевые возможности

> **Полная автоматизация.** "Штатный режим" исключает ручной ввод команд и подтверждения действий.

* **Проверка наличия новой версии**
  * сравнение текущей версии Traefik с последней в релизах GitHub.
  * обновление выполняется только при наличии новой версии.
* **Строгая проверка целостности (алгоритм SHA256)**
  * скачивание файла `checksums.txt` из релиза;
  * поиск суммы для целевой архитектуры;
  * сравнение с вычисленной суммой;
  * прерывание установки при выявлении расхождения контрольных сумм.
* **Безопасный откат**
  * создание резервной копии (`/usr/local/bin/traefik.bak`) перед заменой;
  * возможность ручного отката одной командой.

    <details>
        <summary>📜 "... только добавь воды" </summary>

    ```bash
    mv /usr/local/bin/traefik.bak /usr/local/bin/traefik
    systemctl restart traefik
    ```

    </details>

* **Умный контроль службы**
  * если служба активна, то выполняется `restart`.
  * если служба остановлена, то после обновления выполняется `start`.
  * при ошибках перезапуска применяется `daemon-reload`.
* **Автоустановка зависимостей**
  * определение пакетного менеджера ОС (`apt`, `apk`, `dnf` и т. п.);
  * установка недостающих утилит: `curl`, `jq`, `tar` и другие.
* **Детальный отчет**
  * вывод действий в консоль и запись в отчет `/var/log/traefik/traefik-updater.log`;
  * наглядность цветовых меток состояний (✅ / ❌ / ⚠️).

## 📋 Требования

* **ОС:** GNU/Linux (ядро Linux).
* **Права:** Запуск от имени root (или через `sudo`).
* **Зависимости:** `curl`, `jq`, `tar`, `sha256sum`, `file`.

   >Приложение предпринимает попытку установить зависимости автоматически, но для первичного запуска требуется доступ к репозиториям ОС.

## 💡 Быстрый старт (англ. Quick Start)

1. Скачайте или клонируйте приложение:
   Вариант с curl (основной):
  
    ```bash
    curl -L -o /usr/local/bin/traefik-update.sh https://raw.githubusercontent.com/YOUR_ORG/YOUR_REPO/main/traefik-update.sh
    ```

    Резервный вариант с wget:

    ```bash
    wget -O /usr/local/bin/traefik-update.sh https://raw.githubusercontent.com/YOUR_ORG/YOUR_REPO/main/traefik-update.sh
    ```

2. Дайте права на выполнение:

    ```bash
    chmod +x /usr/local/bin/traefik-update.sh
    ```

3. Запустите обновление:

    ```bash
    sudo ./traefik-update.sh
    ```

> **Важно:** приложение должно запускаться от пользователя `root`, так как он пишет в `/usr/local/bin` и управляет systemd-службами.

## ⚙️ Как это работает (алгоритм)

1. **Проверка ОС и прав:**
   * операционная система семейства GNU/Linux;
   * пользователь имеет права root.
2. **Установка зависимостей (при необходимости):**
   * проверка наличия `curl`, `jq`, `tar`, `sha256sum`.
   * при отсутствии запуск установки через системный пакетный менеджер.
3. **Определение версии:**
   * Сравнение текущей версии Traefik с последней в GitHub API.
4. **Скачивание и проверки:**
    * скачивание архива с бинарником;
    * извлечение архива и проверка наличия исполняемого файла `traefik` для целевой архитектуры;
    * скачивание файла `traefik_vX.Y.Z_checksums.txt`;
    * поиск строки с контрольной суммой для своей архитектуры ЭВМ (например, `linux_amd64`);
    * выполнение сравнения предоставленной контрольной суммы с вычисленной. При расхождении — **остановка и завершение работы**.
5. **Обновление:** создание резервной копии "старого" файла, замена на новый.
6. **Управление службой:** Анализирует статус `traefik.service` и выполняет `start` или `restart`.
7. **Отчет:** Выводит итоговую версию и статус службы.

## 🛠 Настройка под себя

Код Приложения включает начальный раздел с определением общих постоянных/переменных. Внесение изменений позволяет настроить "своё видение":

| Переменная | Назначение | Значение по умолчанию |
| --- | --- | --- |
| LOG_FILE | Путь к отчету | /var/log/traefik/traefik-updater.log |
| BINARY_PATH | Путь и имя, куда устанавливается двоичник Traefik | /usr/local/bin/traefik |
| BACKUP_PATH | Путь и имя, резервной копии Traefik | /usr/local/bin/traefik.bak |
| RED / GREEN / YELLOW / BLUE / NC | Цвета для вывода информации | ANSI-коды |

## ❓ Частые ошибки и решения

| Ошибка / Событие | Причина | Решение |
| --- | --- | --- |
| `Ошибка скачивания checksums.txt` | Проблемы с сетью, блокировка GitHub или временные проблемы API. | Проверьте доступность интернета и GitHub из вашей сети. Повторите запуск позже. |
| `Расхождение контрольных сумм` | Файл скачан с ошибкой или произошла подмена файла. | Приложение **намеренно блокирует установку** в этом случае. Проверьте сеть, очистите временную папку и запустите приложение заново. |
| `Не удалось перезапустить службу` | Конфигурация Traefik (`traefik.yaml`) содержит ошибки, либо диск переполнен. | Посмотрите логи службы: `journalctl -u traefik.service -n 50`. Исправьте конфиг или освободите место. |
| `Приложение падает на установке зависимостей` | В системе отключены репозитории или используется кастомный пакетный менеджер. | Убедитесь, что репозитории ОС доступны. Если система специфическая, установите `curl` и `jq` вручную перед запуском приложения. |
| `Служба не найдена в systemd` | Traefik запущен как Docker-контейнер или через другой менеджер (supervisord, runit). | Приложение не будет пытаться управлять контейнером. Для Docker используйте обновление образа. |
| `Ошибка запуска Службы` | Возможно было принудительное прерывание установки. | Выполните повторный запуск службы. Проверте наличие `/usr/local/bin/traefik`, при отсутствии выполните ручную установку. |

## ⏰ Автоматизация проверки обновления через Cron (раз в неделю)

Чтобы приложение запускалось автоматически (например, каждое воскресенье в 03:00), добавьте задачу в crontab root-пользователя:

Откройте crontab:

```bash
crontab -e
```

Добавьте следующую строку:

```bash
0 3 * * 0 root /usr/local/bin/traefik-update.sh >> /var/log/traefik/cron-traefik.log 2>&1
```

**Примечание:**
💡 Важно: Эта строка добавляется в crontab пользователя root (`sudo crontab -e`). Исключить включение времени запуска в `/etc/crontab` , где формат отличается, возможен сбой при поиске зависимостей.

*Справочно:*
| | |
|---|---|
| 0 3 * * 0 | запуск в 03:00 каждое воскресенье.
| >> /var/log/traefik/cron-traefik.log | ведение отчета вывода сообщений работы приложения.
| 2>&1 | перенаправление ошибок в тот же отчет.

> Совет: Перед включением в Cron обязательно провести испытание приложения вручную (./traefik-update.sh). Убедитесь, что он корректно отрабатывает сценарий «обновления нет» (выходит с кодом 0 и не делает лишних действий).

### 🧪 Проведение "местных" испытаний

Быстрый способ запустить приложение в изолированной среде (Docker):

1. Запуск в контейнере с монтированием приложения

```docker
docker run --rm -it -v $(pwd)/traefik-update.sh:/tmp/traefik-update.sh:ro alpine sh
```

2. Установка зависимостей внутри контейнера:

```docker
apk add curl jq bash
```

3. Запуск приложения (*если в вашей ветке добавлен параметр --dry-run):

```bash
bash /tmp/traefik-update.sh --dry-run
```

**Примечание:** на данный момент параметр `--dry-run` отсутствует. Если вы хотите его добавить — это отличная идея для отдельного ЗВН.

* [ ] **Поддержка большего числа ОС:** добавить определение `pacman` (Arch), `zypper` (openSUSE), `brew` (macOS).
* [ ] **Интерактивный режим:** для тех, кто предпочитает управлять каждым шагом поведения приложения. Например, если зависимости отсутствуют, спросить пользователя: "Установить их за вас? [Y/n]" (по умолчанию режим условный `--force-install`).
* [ ] **Кэширование проверок:** не запускать `command -v` при каждом вызове скрипта, если проверка уже была пройдена.
* [ ] **Автодополнение:** добавить скрипты автодополнения (completion) для Bash и Zsh.
* [ ] **Первичная установка** - проверка наличия установленного "пакета". При отсутствии: подготовка структуры директорий (`/etc/traefik/{conf.d,plugins-storage,ssl}`), окружения (`/etc/traefik/traefik.env` и `/etc/systemd/system/traefik.service`), предоставление прав (`chown traefik:traefik` и `chmod 600`), "подключение" заводских настроек (`traefik.yml`)
* [ ] **Юнит-тесты:** покрыть функцию `check_dependencies` тестами с помощью `bats` (Bash Automated Testing System).
* [ ] **Самодостаточность:** добавить возможность развертывании вне контейнера, а в узле `Proxmox`. Расширив набор переменных, с выносом в отдельный документ `.env` (CT_ID, PVE_NODE, PVE_TOKEN)
* [ ] **Переписать на полноценный язык программирования:** обеспечение управления (установка/обновление/планирование) отдельными службами, в которых этой возможности нет
